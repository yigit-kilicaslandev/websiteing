# How I Built My Personal Portfolio — From Fork to Production

Building a personal website doesn't have to start from scratch. By strategically forking an existing open-source project, I was able to focus on what truly matters — **customization, content, and standing out**.

## Why I Forked Instead of Starting from Zero

The smartest developers know that reinventing the wheel is rarely the best use of time. I found a modern, well-architected portfolio template built with **Astro, TypeScript, and Tailwind CSS** — and forked it to use as my foundation.

This gave me:
- A battle-tested architecture with optimized performance
- Modern tooling (Astro's island architecture, MDX for content)
- A clean, responsive design out of the box

## The Power of `resume.tsx`

The real magic happened in `resume.tsx` — the single source of truth for my entire site. One file controls everything: my bio, work experience, education, skills, projects, and contact information.

Here's what I did:
- **Refactored the data layer** to showcase my projects and competitions
- **Integrated custom icon libraries** (Simple Icons, Lucide) for a polished look
- **Added social integrations** — GitHub, LinkedIn, X (Twitter), and YouTube
- **Configured section ordering** to highlight what matters most
- **Renamed components** — The original template had a "Hackintosh" project reference. I rebranded it with a custom name while keeping the internal file references (`hakintosh`) intact for backward compatibility

## Tech Stack Highlights

| Technology | Purpose |
|------------|---------|
| Astro | Static site generation with island architecture |
| TypeScript | Type-safe data structures and components |
| MDX | Rich blog content with component support |
| Tailwind CSS | Utility-first styling for rapid development |
| Lucide Icons | Clean, consistent iconography |

## Key Takeaways

1. **Fork strategically** — Choose a project with solid architecture and an active community
2. **Customize deeply** — Don't just change colors; refactor the data model and add your own features
3. **Keep content in one place** — The `resume.tsx` pattern makes updates trivial
4. **Deploy with confidence** — Astro's static output means zero server costs and instant page loads

## What's Next

I'm continuing to iterate on the site — adding more projects, refining the design, and building out the blog section. The fork gave me a head start, but the **customization** is what makes it mine.
